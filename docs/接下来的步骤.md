## 第二步：配置云存储（否则上线后附件会消失）

### 2.1 拿两个值

| 要什么 | 在哪 |
| --- | --- |
| **Project URL** | [Supabase](https://supabase.com/dashboard/project/sfjpiueporzqznchaxsx/settings/api) → 左侧 **Data API** → 复制 Project URL |
| **Secret key** | 同一页面的 **API Keys** → 下半部分 **Secret keys** → 点 👁 或复制按钮 |

> ⚠️ Supabase 改过名：老的 `service_role` 现在叫 **Secret key**（`sb_secret_...`），
> 老的 `anon` 现在叫 **Publishable key**（`sb_publishable_...`）。
> **我们要的是 Secret key。** 如果界面上找不到，点 `Legacy anon, service_role API keys` 标签能看到旧名字。

### 2.2 填进 .env

```ini
SUPABASE_URL="https://sfjpiueporzqznchaxsx.supabase.co"
SUPABASE_SERVICE_ROLE_KEY="sb_secret_你复制的那一长串"
```

> ⚠️ **Secret key 权限极高**（等同数据库管理员），绝不能进公开仓库、不能截图分享。
> 截图时记得先打码。

### 2.3 验证

```powershell
node scripts/preflight.mjs
```

那条 `[注意] 没配 Supabase 存储` 应该变成 `[通过]`。

然后**重启 dev server**，发一条带附件的帖子测试。

## 第三步：部署到 Vercel

详细步骤见 [部署指南](部署指南.md)，这里是精简版：

### 3.1 导入项目

1. 打开 [vercel.com/new](https://vercel.com/new)，用 GitHub 登录
2. 找到 `campus-forum` 仓库 → **Import**

### 3.2 填 5 个环境变量（**最容易漏**）

在 Import 页面展开 **Environment Variables**，逐个加：

| 变量名 | 值 |
| --- | --- |
| `DATABASE_URL` | 本地 `.env` 里的那一行（端口 6543 的连接池地址） |
| `DIRECT_URL` | 本地 `.env` 里的那一行（端口 5432 的直连地址） |
| `SUPABASE_URL` | 同第二步 |
| `SUPABASE_SERVICE_ROLE_KEY` | 同第二步 |
| `NEXT_PUBLIC_SITE_URL` | **先留空**，部署完拿到网址再回来填 |

漏掉任何一个的后果：网站能打开，但一操作就白屏或报错，错误在 Vercel 的 **Functions 日志**里。

### 3.3 点 Deploy

等一两分钟。失败的话点 **Building** 看日志，往下翻找 `Error`。

### 3.4 拿到网址后补一个变量

Vercel 会给一个 `https://campus-forum-xxx.vercel.app` 的地址。
把这个地址填进 `NEXT_PUBLIC_SITE_URL`，然后 **Redeploy** 一次
（改了环境变量必须重新部署才生效）。

## 第四步：同步数据库表结构

**Vercel 只跑网站，不改表结构。** 迁移在你自己电脑上做：

```powershell
cd D:\tool\Code\Git
npx prisma migrate deploy
```

> 不要用 `migrate dev` —— 它需要创建「影子数据库」，而 Supabase 免费版没这个权限，会**卡住不动**。

---

## 第五步：上线后逐项验收

**每一项都要真的点一下**，不要只看代码：

| 检查 | 预期 | 出问题看哪 |
| --- | --- | --- |
| 打开首页 | 板块列表能显示 | Vercel Functions 日志 |
| 注册账号 | 跳回首页、顶栏显示昵称 | Functions 日志（多半是 `DATABASE_URL`） |
| 发帖 | 帖子出现在列表 | Functions 日志 |
| 传附件 | 能上传能下载 | Functions 日志（多半是 Supabase 密钥） |
| 手机打开 | 板块是可横滑的胶囊条 | — |
| **在 Vercel 点一次 Redeploy** | 之前传的附件**还在** | 如果没了 → 存储没切到云端 |

最后那条特别重要：它是**唯一能验证「文件真的存到云端了」的方法**。
本地硬盘在容器里，重启就没了；云存储不会。

## 可选：接真实邮件服务

不接也能上线 —— 注册会成功，只是验证邮件打在 Vercel 日志里，用户收不到。

要接的话：

1. 去 [resend.com](https://resend.com) 注册（GitHub 登录，免费额度每月 3000 封）
2. 创建 API Key，填进 Vercel 环境变量 `RESEND_API_KEY`
3. 重新部署

**注意**：没自己的域名时，只能用 Resend 的测试发件地址，它**只能往你自己注册时用的邮箱发信**。要发给别人得先验证域名（买个便宜域名一年几十块）。

