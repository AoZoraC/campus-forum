# 部署指南

> 把「能在我电脑上跑」变成「同学能打开网址用」。
> 这份文档按顺序列出每一步，以及**每一步容易出问题的地方**。

---

## 部署前的准备清单

| 项目 | 状态 | 说明 |
|---|---|---|
| 代码推到 GitHub | ☐ | `git push` 成功 |
| Supabase 数据库 | ☐ | 已在用，表都建好了 |
| Supabase Storage | ☐ | 需要拿 `SUPABASE_URL` 和 `SERVICE_ROLE_KEY` |
| Vercel 账号 | ☐ | 用 GitHub 登录，免费 |
| 邮件服务 | 可选 | 不接也能上线，只是收不到验证信 |

---

## 第一步：把文件存储切到云端

**为什么必须做**：Vercel 的文件系统是临时的，每次部署或冷启动都可能换一个容器，
你上传的课件会凭空消失。

1. 打开 Supabase 项目 → 左侧 **Project Settings** → **API**
2. 复制 **Project URL**（形如 `https://xxxxx.supabase.co`）
3. 复制 **service_role** 密钥（在 `Project API keys` 里，**不是 anon 那个**）
4. 填进本地 `.env`：

```ini
SUPABASE_URL="https://你的项目ID.supabase.co"
SUPABASE_SERVICE_ROLE_KEY="eyJhbGci..."
```

5. 重启 `npm run dev`，发一条带附件的帖子试试

> ⚠️ `service_role` 密钥**绕过所有安全检查**，等同数据库管理员。
> 它只能出现在服务端环境变量里，绝不能进前端代码或公开仓库。

---

## 第二步：部署到 Vercel

### 1. 注册并导入项目

1. 打开 [vercel.com](https://vercel.com)，用 **GitHub 账号**登录
2. 点 **Add New** → **Project**
3. 找到 `campus-forum` 仓库 → 点 **Import**

### 2. 配置环境变量（**最容易漏的一步**）

在 Import 页面的 **Environment Variables** 区域，逐个添加：

| 名称 | 值从哪来 | 备注 |
|---|---|---|
| `DATABASE_URL` | 本地 `.env` 里那一行 | 连接池地址，端口 6543 |
| `DIRECT_URL` | 本地 `.env` 里那一行 | 直连地址，端口 5432 |
| `SUPABASE_URL` | 同上 | |
| `SUPABASE_SERVICE_ROLE_KEY` | 同上 | |
| `NEXT_PUBLIC_SITE_URL` | 先留空，部署完拿到网址再回来填 | 用于拼邮件里的链接 |

**漏掉任何一个的后果**：网站能打开，但一操作就白屏或报错，而错误信息通常在
Vercel 的 **Functions** 日志里（不在浏览器控制台）。

### 3. 点 Deploy

等一两分钟。构建过程会：
1. 安装依赖
2. 跑 `postinstall` → `prisma generate`（生成数据库客户端）
3. 跑 `next build`

**构建失败的话**，点 **Building** 那一步看日志，往下翻找 `Error`。

### 4. 拿到网址

部署成功后会得到一个形如 `https://campus-forum-xxx.vercel.app` 的地址。
**这就是你能发给同学的网址。**

拿到之后回到 Vercel → Settings → Environment Variables，
把 `NEXT_PUBLIC_SITE_URL` 填成这个网址，然后 **Redeploy** 一次
（改了环境变量必须重新部署才生效）。

## 第三步：处理数据库迁移

**关键概念**：Vercel 只负责「跑网站」，**不负责改表结构**。
迁移要在你自己的电脑上跑。

```powershell
cd D:\tool\Code\Git
npx prisma migrate deploy
```

这条命令做两件事：读 `prisma/migrations/` 里的 SQL 文件，
把还没应用的依次执行到线上数据库。

> 为什么不用 `migrate dev`？因为它需要创建「影子数据库」来检测漂移，
> 而 Supabase 免费版的账号没有这个权限，会**卡住不动**（我们踩过这个坑）。

**验证**：跑 `node scripts/db-status.mjs`，应该能看到所有表。

## 第四步（可选）：接真实邮件服务

不接也能上线 —— 注册会成功，只是验证邮件打在 Vercel 日志里，用户收不到。

要接的话：

1. 去 [resend.com](https://resend.com) 注册（GitHub 登录，免费额度每月 3000 封）
2. 创建 API Key，填进 Vercel 环境变量 `RESEND_API_KEY`
3. 重新部署

**注意**：没自己的域名时，只能用 Resend 的测试发件地址，
它**只能往你自己注册时用的邮箱发信**。要发给别人，得先验证一个域名
（买个便宜域名一年几十块）。

## 上线后的检查清单

按顺序试一遍，**每一项都要真的点一下**：

| 检查 | 预期 | 出问题看哪 |
|---|---|---|
| 打开首页 | 板块列表能显示 | Functions 日志 |
| 注册一个账号 | 跳回首页、顶栏显示昵称 | Functions 日志（多半是 `DATABASE_URL`） |
| 发一条帖子 | 帖子出现在列表里 | Functions 日志 |
| 发帖时传附件 | 能上传、能下载 | Functions 日志（多半是 Storage 密钥） |
| 手机打开 | 板块是可以横滑的胶囊条 | — |
| **重启一次部署** | 之前上传的附件**仍在** | 如果没了，说明文件还存在本地硬盘（Storage 没配好） |

最后那一条特别值得做：它是**唯一能验证「存储真的切到云端了」的方法**。
本地硬盘在容器里，重启就没了；云端存储不会。

## 常见问题

**构建失败：`prisma generate` 报错**
→ 检查 `DATABASE_URL` 是否填了。虽然 generate 本身不需要数据库，
但我们的 `prisma.config.ts` 会读环境变量。

**页面能打开，但一登录就报错**
→ 八成是环境变量没填全。Vercel 的环境变量改动**需要重新部署**才生效。

**上传文件报 413 / 请求体过大**
→ `next.config.ts` 里的 `serverActions.bodySizeLimit` 没生效，
确认文件已提交、且重新部署过。

**同学说「打不开」**
→ Vercel 的默认域名在国内访问可能偏慢或偶尔不通。
真要长期用，考虑买个域名 + 备案，或者换国内服务器。
